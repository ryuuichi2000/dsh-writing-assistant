# 公文起草共享规则

本文件是所有文种共用的写作与交付规则。起草前先读本文件，再读 `references/doc-types/<文种>.md`。
文种参考里只写该文种特有的内容，不重复本文件的通用规则。

---

## 1. 事实与政策边界（硬约束）

### 1.1 零幻觉

成稿中的每一个具体值——事实、数据、文件号、机关名称、人名职务、时间地点、会议结论、政策法律依据——只有两种合法状态：

1. 有来源：用户本次提供，或经检索核实、可指出出处的公开来源；
2. 是占位符：写成 `[发文单位]`、`[日期]`、`[待核实]`、`[具体金额]` 等。

没有第三种。不得把推测、常识补全、经验判断或“看起来像真的”写成确定事实。

### 1.2 不得编造

- 不编造政策依据、文件号、法律条款、会议结论、机构名称、人员身份、统计数据、时间地点、新闻事实。
- 不虚构上级精神、领导讲话、批示、调研结论。
- 不把网络传闻、二手转述、未核实截图当作事实。
- 引用公开材料时，借鉴的是结构、写法和真实公开事实，不是凭空生成内容。

### 1.3 信息不足时

- 结构性字段缺失：保留占位符，不删章节。例如 `[主送单位]：`、`[发文单位]`、`[日期]`。
- 事实性内容缺失：写 `[待核实]` 或在句中标注“（待核实）”，不要用模糊表述掩盖。
- 关键事实缺失且影响成稿成立：先向用户追问，一次问清最关键的 3—5 项，不要边写边猜。
- 用户提供的材料互相矛盾：采用保守表述，并在成稿外单独说明冲突点，请用户确认。

### 1.4 时效与来源

- “当前”“最新”“近日”“今日”等表述，必须以用户提供或已核实的日期为准；没有日期就标“待核实”。
- 联网检索时优先 `.gov.cn`、发文机关官网、原始文件、权威媒体；记录标题、发布机关、发布日期、链接。
- 检索到的内容写进同目录 `materials.md` 或 `-来源.md` 台账，成稿正文不堆 URL。
- 引用统计数据要交代口径和时点；口径不明的不写具体数值。

### 1.5 人工复核

涉及正式发文、对外报送、政策法律敏感、涉密、涉隐私、可能产生权利义务影响的文本，必须由具备相应权限的人员审核后才能使用。本技能产出的是**初稿**，不是可以直接签发的定稿。

## 2. 文种与行文方向

### 2.1 文种范围

- **法定公文 4 种**：通告、函、通报、纪要（决议已按用户要求从模板列表移除，不再作为入口）。
- **常见正式材料 4 类**：情况专报、讲话稿、工作总结、危机处置报告。
- 合计 8 个入口。法定公文用法定名称，不自造文种，不混用。

### 2.2 文种路由

| 需求 | 文种 |
| --- | --- |
| 一定范围内公布应当遵守或周知的事项 | 通告 |
| 平行或不相隶属机关商洽、询问、答复 | 函（答复用复函） |
| 表彰先进、批评错误或传达重要情况 | 通报 |
| 记载会议情况和议定事项 | 纪要 |
| 报送专题信息、风险、舆情 | 情况专报 |
| 领导讲话、会议发言、动员部署 | 讲话稿 |
| 阶段复盘、年度总结、专项总结 | 工作总结 |
| 发生安全事件/突发事件，或收到主管部门整改通知后向相对方报告 | 危机处置报告 |

判断顺序：先定行文方向（下行/平行/公开/内部），再定目的（告知/商洽/记载/报送/讲话/复盘），最后落到文种。

### 2.3 易混文种辨析

- **通报 vs 通告**：通报对内，表彰/批评/告知情况；通告对外，公布应共同遵守的事项，带强制语气和法律依据。
- **决议 vs 纪要**：决议必经会议讨论表决、以会议名义发布，写表决形成的决定；纪要记载会议情况和议定事项，不写表决程序。（决议已移出模板列表，这条只用来划清纪要的边界。）
- **函 vs 通报**：不相隶属或平行机关之间商洽、询问、答复一律用函；通报用于本系统内的表彰、批评或情况传达。
- **情况专报 vs 通报**：专报面向领导或上级，重在风险研判和工作建议；通报面向一定范围，重在事实、评价和要求。
- **纪要 vs 记录**：纪要提炼议定事项、需审定印发；记录是原始逐字存档。未达成一致的不写入议定事项。
- **工作总结 vs 情况专报**：总结面向阶段性复盘，写做法、成效、问题、打算；专报面向单一专题，写事实、研判、建议。

### 2.4 行文常识

- **确有必要**：可发可不发的不发；不重复行文。
- **不越级**：一般不越级行文；确需越级的，同时抄送被越过的机关。
- **不径送领导个人**：除领导直接交办外，不以本机关名义向上级机关负责人报送公文。
- **联合行文有限**：党委、政府各自职权范围内的工作不联合行文；部门内设机构除办公厅（室）外不对外正式行文。

## 3. 起草流程

1. **定文种与方向**：按 2.2、2.3 判定；拿不准时先用一句话向用户确认。
2. **盘清输入**：按目标文种参考的“起草前确认”逐项核对；缺关键项先问，缺格式项留占位。
3. **列提纲**：先写各板块标题和一句话主旨，确认逻辑链（为什么写—做到哪里—卡在哪里—下一步怎么办）。
4. **起草**：按提纲逐段写，先保证文种正确、结构完整，再打磨语言。
5. **事实核对**：逐句检查具体值是否有来源；无来源改占位或标“待核实”。
6. **机器校验**：运行 `scripts/check_draft.py`，处理硬错误，逐条看提示。
7. **人工校对**：错别字、病句、标点、数字、日期、称谓、机构名称、职务排序。
8. **导出 Word**（需要时）：先确认 Markdown 结构，再导出。

写作时先想清楚三个问题：**给谁看、要他做什么、凭什么信**。回答不了就不要动笔。

## 4. 结构与语言

### 4.1 标题

- 格式：发文机关 + 事由 + 文种，如“XX单位关于XX情况的通报”；无须重复发文机关时可省略。
- 事由用“关于……”；标题直接点明事项和文种，不写“有关问题”“相关事宜”这类含糊词。
- 一个标题只写一个中心事项；不层层叠加“关于……的……的……”。
- 标题一般不用标点；法规、规章、文件、方案名称用书名号《》，专有名称必要时用引号。
- 标题较长可回行，保持词意完整、排列对称，优先逐行等长或递减；不把“关于”“的”等虚词甩到行末。
- 标题末尾不加句号。

### 4.2 层次序号

- 第一层：`一、`（汉字 + 顿号）
- 第二层：`（一）`（括号 + 汉字，不加标点）
- 第三层：`1.`（阿拉伯数字 + 实心圆点）
- 第四层：`（1）`（括号 + 阿拉伯数字）
- 逐级展开，不跳级、不混用（不要出现“一是、（二）、3.”混排）。
- 一般不超过三级；10 页以内以二级为主，材料确实复杂时才下钻三级。不为层数而分层。
- `一是、二是、三是` 是段内分点衔接语，不是层级标题；默认在同一自然段内连续书写，不各起一段。
- 一级标题可单独成行（整行黑体），也可与正文同段、只把标题短语排黑体；两种写法全文统一。

### 4.3 段落

- 正文首段先交代背景、目的或依据，再展开具体事项、答复意见或工作安排。
- 每个板块要回答它该回答的问题：背景答“为什么写”，进展答“做到哪里”，问题答“卡在哪里”，要求答“下一步做什么、谁来做、何时做”。
- 二级标题下可先概述 2—4 句，再用“一是、二是、三是”分点；**篇幅服从事实密度，不为凑句数编造或注水**。
- 一段一个中心意思；长句拆短，避免一逗到底。
- 首次出现非规范简称、项目简称、机构简称、会议简称时，先写全称，再用括号注明简称，后文统一。
- 引用文件先写标题、再写发文字号；引用会议先写完整名称和届次；届次、文号、日期写全。

### 4.4 开头

按事项性质四选一，也可叠用（先依据后目的），但开头不超过三句就转入主体：

- **缘由式**：交代触发事项。“近期，……”“根据……反映，……”
- **依据式**：先引上位依据。“根据《……》和……会议精神，……”
- **目的式**：以“为了……”统领。“为深入贯彻……，现就……通告如下：”
- **导语式**：先概括后分述。多用于情况专报、纪要。

### 4.5 结尾

结尾套语与文种绑定，不张冠李戴，也不与开头“现将……如下”重复：

| 文种 | 结尾 |
| --- | --- |
| 函 | 特此函达。/ 特此函商。/ 请予支持为盼。 |
| 复函 | 特此函复。 |
| 通告 | 特此通告。/ 本通告自……起施行。 |
| 通报 | 现提出以下工作要求…… / 希望……引以为戒。 |
| 危机处置报告 | 特此报告。 |

- 纪要一般不写寒暄式结尾，议定事项写完即收束。
- 情况专报直接收束到事实、研判和建议，不加套语。
- 讲话稿以现场收束语结尾，工作总结以下一步安排收束，不套用“特此”。

### 4.6 语域（正式度）

三档，按对象和场合选择：

1. **事务级**：内部材料、便条、口头汇报，务实灵活。
2. **单位正式级**：一般机关公文、企业对外正式材料，**默认档**。
3. **省部级政论级**：中央、部委高规格行文，政论笔法 + 精确引据 + 严整结构。

- 默认按第 2 档起草；用户明确面向中央/部委、上行重要文件或要求“高规格”时，才升到第 3 档。
- 无论哪档，都不为“文气”编造事实、数据或依据。
- 上行不卑、下行不傲、平行不命令。

#### 口语化红线

- **除讲话稿外，其他文种零口语**：不出现第二人称劝阻、口语动词、网络词、反问和感叹。
- **讲话稿是“书面语 + 少量口语色彩”**：口语色彩（引述、比喻、现场提醒）全篇不超过三处，且不落在小标题、任务要求和结尾号召上。
- 口语黑名单：使劲、搞定、踩坑、翻车、拉胯、说白了、一句话、不要等……再……、千万别、越……越……。
- 判定方法：把句子单独念出来。像在会上讲话是合格的，像在微信群里说是超标的。

### 4.7 小标题

- 写成“动词＋对象，动词＋目标”的并列双句，句式对齐，6—20 字。
- 不用冒号引出解释（“认清形势：……”），不设问，不喊口号，不用口语动词。
- 正例：坚持精品出版，把社会效益放在首位；完善把关机制，守好内容安全底线。
- 反例：认清形势：政策和市场都在往“高质量”上使劲。

### 4.8 数字与标点

- 年份、统计、计量、编号用阿拉伯数字；年份写全，不用两位。
- 概数、成语、惯用语、定型词用汉字（如“三天”“十几个”“十一五”）。
- 成文日期用阿拉伯数字，年份写全，月日不补前导零：`2026年6月1日`。
- 发文字号：机关代字 + 六角括号〔年份〕+ 顺序号 + “号”，不加“第”、不补零：`〔2026〕5号`。
- 百分数、金额、计量单位全文统一；范围用“30%—40%”，不用“30%~40%”混排。
- 标点按 GB/T 15834：中文文本用全角标点，不用英文逗号、句号、括号；书名号、引号成对。
- 分号只在并列结构确需时使用；能用句号断开就断开。
- 2012 版公文格式已取消“主题词”，不编排。

### 4.9 常见语病与空话

- 空泛表态：认真抓好落实、高度重视、切实加强、不断完善——后面必须跟具体动作。
- 搭配不当：开展水平、提高工作、加强力度——改为“提高水平”“加大力度”“推进工作”。
- 生造简称：未经说明的“两办”“一网通办”式缩略，首次出现写全称。
- 一逗到底：超过 80 字不断句，拆成两到三句。
- 重复冗赘：“关于……的问题的情况说明”层层套叠。
- 称谓语混用：同一单位在全文中全称、简称统一；同一名单排序统一。
- 口号化：没有主语、没有动作、没有时限的句子，删掉或改写。

## 5. 版式与 Word 导出

### 5.1 GB/T 9704-2012 要点

- A4 纸，版心 156mm×225mm；页边距上 37mm、下 35mm、左 28mm、右 26mm。
- 正文 3 号仿宋，一般每面 22 行、每行 28 字；首行缩进 2 字符。
- 标题 2 号小标宋，居中；一级标题 3 号黑体，二级标题 3 号楷体，三级、四级标题 3 号仿宋（不加粗）。
- 主送机关在标题下空一行，顶格，末尾全角冒号。
- 正文与落款之间空 3 行；成文日期用阿拉伯数字。
- 页码 4 号宋体，数字两侧加一字线（— 1 —）；单页码居右空一字，双页码居左空一字。
- 版记要素通常为抄送机关、印发机关和印发日期；不是所有文种的必备结构。

### 5.2 结构板块顺序

标准顺序：

```
标题
主送单位（视文种）
正文
附件说明（有附件时，正文下空一行左空二字“附件：”）
落款（发文机关署名 + 成文日期）
附注（有联系人、公开属性等时，成文日期下一行左空二字，加圆括号）
版记（按本单位模板，可选）
```

- 附件本身另面编排，放在版记之前；附件说明只列名称和顺序，不抄附件全文。
- 图片、流程图、示意图优先放附件/附图；正文只写“详见附件”。
- 附图放在附注之后、版记之前，图片居中，图号、标题、说明、来源齐全。

### 5.3 字体方案

| 方案 | 标题 | 一级标题 | 二级标题 | 正文 | 适用 |
| --- | --- | --- | --- | --- | --- |
| `official-standard` | 方正小标宋简体 22pt | 黑体 16pt | 楷体_GB2312 16pt | 仿宋_GB2312 16pt | 法定公文 |
| `internal-readable` | 黑体 22pt | 黑体 16pt | 楷体_GB2312 16pt | 仿宋_GB2312 16pt | 情况专报、工作总结 |
| `speech-readable` | 黑体 22pt | 黑体 16pt | 楷体_GB2312 16pt | 仿宋_GB2312 16pt | 讲话稿、发言稿 |

- 本技能**不捆绑字体文件**，只写字体名；目标机器需已安装对应字体。
- 没有上述字体时：在 Word 中替换为系统字体，或导出时加 `--font-preset noto-cjk` / `--font-preset fandol` 使用开源替代。
- `方正小标宋` 为商用字体，使用和分发前自行确认授权。

### 5.4 落款、附注、版记、页码

- 加盖印章版：成文日期右空 4 字，发文机关署名居中压在日期上方。
- 不加盖印章版（电子版）：日期右空 2 字，署名首字比日期首字左移 2 字；导出时加 `--unsealed`。
- 附注不是必备要素：只有用户提供联系人、联系电话、公开属性，或本单位模板要求时才保留；不默认生成联系人占位。
- 版记不是默认结构：按本单位模板或用户要求编排，通常包括抄送机关、印发机关、印发日期；`审核` 等属内部流转字段，不写进正文。
- 插件导出默认采用首页起算、版心底部居中的纯数字。选择带一字线样式及外侧位置可生成奇右偶左页码。信函等需要隐藏首页时可单独关闭首页显示，第二页仍为 2。

### 5.5 图片与附件

- 导出器支持 `![图1 标题](./本地图片.png)` 独立成块；仅 png/jpg/jpeg，图片必须在成稿同目录或子目录，不能 `../` 越级。
- 图片按原始像素尺寸排版，超过版心时等比缩小，不把小题图放大到整版宽。
- 图片不裸放：要有图号、标题、说明；来源、拍摄时间、数据截止时点、适用范围按需注明。
- 页眉/页脚图片用 `--header-image` / `--footer-image` 指定，可以是本地路径或图库名称；首次使用路径会自动保存到 DSH 数据目录的 `doc-images/`，之后按名称复用。
- 页眉图片默认宽 35mm、页脚默认宽 30mm，可调；图片按宽度等比缩放，并限制最大高度，避免压到正文。
- 首页不显示页码时，页眉图片仍显示在首页；页脚图片在首页只放图片、不放页码。

## 6. 交付与自检

### 6.1 输出

- 默认输出**完整 Markdown 成稿**；用户只要提纲时输出提纲。
- 成稿中不写模型自我说明、不写“以下是……”“希望对你有帮助”。
- 用户要求 Word 时，先确认 Markdown 结构正确，再导出 `.docx`。
- 未指定文件名时：`YYYYMMDD-标题-vNN.md`；同一天同一标题递增版本号，不覆盖旧稿。
- 未指定目录时，保存到当前工作目录下的 `公文/`；用户指定路径时以用户为准。
- 需要检索时，把核实过的来源写入同目录 `materials.md` 或 `-来源.md`；成稿正文不堆链接。

### 6.2 机器校验

```bash
python scripts/check_draft.py <文种> <成稿.md>
```

- 校验章节完整性、结构顺序、层级跳级、格式红线、结尾用语、未填占位符、附件位置、危机处置报告三部分完整性等。
- `--strict` 把警告升级为错误；`--facts` 列出非占位的具体值，供逐项核对来源。
- 机器校验只做提示，最终以人工校对为准。

### 6.3 人工校对清单

- [ ] 文种、行文方向、主送对象正确，没有把通告写成通报、把函写成通报。
- [ ] 标题事由和文种准确，无句号，无层层转发。
- [ ] 层次序号逐级、统一，没有跳级和混用。
- [ ] 每个板块都回答了它该回答的问题，没有空标题、空段落。
- [ ] 事实、数据、文号、日期、人名职务都有来源或占位。
- [ ] 数字、标点、计量单位全文统一。
- [ ] 机构名称、简称、职务排序前后一致。
- [ ] 结尾套语与文种匹配。
- [ ] 附件说明、落款、附注、版记位置正确。
- [ ] 通读一遍，删掉所有可以删的套话。

## 7. 兜底骨架

没有匹配到具体文种，或用户只要一个通用结构时，按下列骨架起草，并在成稿前说明所用结构。

- **通告**：标题 → 发布缘由 → 通告事项 → 执行要求 → 落款
- **函**：标题 → 主送 → 事项缘由 → 主要意见 → 配合事项 → 结尾 → 落款
- **通报**：标题 → 主送 → 基本情况 → 评价分析 → 工作要求 → 落款
- **纪要**：标题 → 会议信息 → 正文（认为/指出/强调/决定）→ 落实要求 →（版记）
- **情况专报**：标题 → 报送对象 → 事项概况 → 最新进展 → 风险研判 → 工作建议 →（落款）
- **讲话稿**：标题 → 称谓 → 开场说明 → 形势判断 → 重点任务 → 工作要求 → 结束语
- **工作总结**：标题 → 基本情况 → 主要做法 → 工作成效 → 存在问题 → 下一步打算 →（落款）
- **危机处置报告**：标题 → 主送单位 → 开头 → 事件情况 → 处置经过 → 整改情况 → 特此报告 → 落款（内部小节按内容命名，时间线或问题线二选一，不套固定四段）
