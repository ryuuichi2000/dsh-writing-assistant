# 文章写作 · 任务单与写法（唯一规则正文）

这份文件是文章写作的唯一写法入口。`gallery/prompts.js`、`lib/jobs.js`、`lib/skills.js`、`SKILL.md` 只指向这里，不再各自维护一套互相冲突的配额。`style-analysis.md` 保留作者样本的观察，但**观察不是硬指标**；与用户原话冲突时，以用户原话为准。

## 一、先把用户原话拆成任务

写之前，从题目/委托里提取并写进任务卡（brief）：

- **核心问题**：读完这篇文章，读者要能回答的那个问题。
- **对象、地域、时间**：写的是哪个市场、哪类公司、哪个时间段。
- **期望的判断数**：用户说“分 2—3 点”就写 2—3 个判断，**不要为凑三节硬加第三节**；说“从三个角度”是三个可覆盖的角度，不必等于三节。
- **要覆盖的角度**：例如品类、消费、行业、出海、政策、公司。用户点到的角度优先；没有点到的，按论证需要取舍。
- **证据要求**：是否需要数据、是否允许检索、有哪些现成材料。
- **标题归属**：用户给的是完整标题，还是只给了委托、要你自拟题目。

用户原话可以是一句完整委托，也可以已经是一个成稿标题。程序会区分并写进任务快照：

- **用户给定标题**：原样使用，不改成“短、转折、问句”，不加副标题，不改写。
- **用户给的是委托**：自拟标题。标题要能让列表里的读者辨认对象、时间和这篇文章要回答的问题；可以用短语，也可以用问句，但不设固定句式。
- **委托里常夹着材料要求**（“用《某作》的玩法材料说清楚”“结合给出的数据说明”）：这半句属于委托，不是标题；标题只保留对象、时间和问题，材料要求放进任务卡和正文，不要原样抄成标题。

用户明确提出的约束高于本文任何默认值。只出现一个未来年份、提到一部将上映的电影或引用历史预测，**不构成预测任务**。

## 二、只在这四种任务里选一种

1. **预测**：用户要求判断未来（“2027 年市场会怎样”“明年的增量从哪里来”）。启用下面的预测规则。
2. **机制**：用户问“为什么/怎样/靠什么”（“女性向游戏怎样吸引泛用户”）。重点解释因果、参与者和约束，不做未来展望。
3. **争议**：用户问“是否/该不该/是不是不务正业”。双方最强论据都要摆出来，再给有条件的判断；不写成两边各打五十大板。
4. **一般分析**：解释一个现象或一组数据，不强制预测。

任务类型不是文风标签，而是决定**要不要写条件、要不要给未来判断**。非预测题不要为了“完整”硬加未来展望。

## 三、提纲先回答实际问题（扩写前检查点）

分析型任务必须先把提纲交给 `writing_save_outline`，Host 检查通过后才允许 `writing_save_work`。提纲至少包含：

- **主线一句话**：这篇文章要让读者改变哪个判断。
- **每节一个判断或可检验的问题**：不是“品类”“消费”“行业”这种栏目名，而是“2027 年的增量更可能来自小游戏付费还是端游回流”这类要回答的问题。
- **每节的证据**：用哪条台账、哪组数字、哪个反例。没有证据就写“缺口”，不要编。
- **预测稿的成立条件**：基线是多少、按什么增速/机制推、哪些变量会改变结论。

预测稿的提纲格式（可自由组织，但四类信息不能缺）：

```
## 第 1 节：这一节要回答的判断/问题
判断：……
基线：目标期之前的实际值、口径、期间
机制与证据：为什么可能变化；哪条来源/数据支持
条件：什么情况下这个判断不成立
```

写不出“基线”或“条件”的预测节，宁可缩小问题、给条件判断，或写“现有资料无法回答”，不要用形容词补齐。

读者看到的正文不必保留“判断/基线/证据/条件”这些标签；标签是给编辑审阅的，正文要写成自然段落。

## 四、证据、推算和待核分开

台账里至少有四种文字，强度不同：

- **来源**：外部报告、媒体、公告、访谈。写清发布者、日期、口径；能打开原文再摘录。
- **口径说明**：同一指标能不能相加、不同机构的口径差异。正文不要混用。
- **本文推算**：作者按基数、期间、公式算出来的值。必须写“按……推算/粗算”，并给出基数、区间、公式；不能写成“据……显示”。
- **待核**：缺口、冲突、没有名单支撑的判断。正文可以保留为“待核”，不能把它再抄进台账当成已核实。

程序会检查：

- 百分比与百分点、市场收入与用户支出、国内与海外、百强移动游戏与全市场，必须带口径。
- 相同数字出现在台账里，不等于这个主张成立；要看来源是否支持这个结论的强度。
- 区间算术不是概率。3750–3800 亿元按 5%–6% 外推，端点是 3937.5 和 4028；若基数 3750，达到 4000 需增长约 6.67%，若 3800 需约 5.26%。这是情景计算，不是“大概率突破”的依据。
- 人均贡献 = 收入 ÷ 用户数，是算术结果；它不能推出“单价涨了”。要谈价格，补 ARPU、付费率、客单价或具体定价证据。
- 单期品类收入占比不能推出“钱流向了某个品类”；要写流向变化，补同口径的跨期数据、留存/新品供给或企业选择证据。
- “只剩百人以上团队那几家”如果没有企业名单，就是待核判断；改写条件句或删掉，不要靠重复台账洗白。

外部资料明确给出的估计可以引用，但要保留估计者和假设。没有概率依据时，不写“大概率/必然/势必/有望”。

## 五、结构与中文

写正文或大幅重写前，先读 [起稿与成文](wechat-analysis/drafting.md)：以真实材料开稿、让对象和动作先出现、每段增加一项读者需要的信息。下面是这一阶段要守的硬边界。

- 结构服从题目和证据，不套“现状—问题—建议”，不强制 3—5 节，不强制每节同形。
- 每节先给具体事实或一个可检验的问题，再给判断；事实段可以过去时，预测段要交代方向、时间和条件。
- 标题、导语、各节判断、结论要能独立读出一个一致的观点；不能标题承诺 2027，正文前两节只解释历史，预测全压在末节。
- 中文自然：对象明确、判断克制、少空话。不要为了“像作者”复制样本里的署名、口头禅或原句。
- 不设“必须有一个人物/场景”“必须有 2—3 个比喻”的配额；需要时用具体动作或产品选择解释机制，不需要时零比喻也可以。
- 不堆“随着……发展”“综上所述”“值得注意的是”“赋能/闭环/生态/底层逻辑”这类词；不排比三连，不每段都用“不是 A，是 B”。
- 正文不挂 `[1]`、①、（数据来源：…）；出处写在句子里，文末用 `## 参考资料` 列全来源。
- 篇幅按用户约定：统计正文汉字时剔除文末参考资料和链接（插件显示的字数就是这个口径）。上限要守——超出约定 10% 就删掉重复交代、无关背景和过长引文；下限不硬凑，内容不足时写明缺口。不要把“约 1500 字”当成可以随便放宽的参考值。

## 六、交稿前的三轮修订

1. **第一轮看判断**：标题、导语、每节第一段、结论是否回答同一个问题；有没有为凑节数加的段落；预测节有没有基线和条件。
2. **第二轮看证据**：每个具体数字/引文能否回到台账；作者推算有没有写成外部来源；有没有用单期数据推跨期、用人均推价格、用区间算概率。
3. **第三轮看句子**：读 [审稿与保真回读](wechat-analysis/editing.md)。先删空转（能套到任何行业的开头、没有指明的“业内认为”、用比喻重复刚说过的事、段尾拔高），再补主语和动作、破掉整篇同构的段落走法；改完逐项回读数字、单位、日期、口径、主语、引语、否定和条件。只润色一段时守住选区，交“原句→改句→理由”，不顺手改选区外的话。

写完之后按上面三轮走一遍；程序审校返回 `error` 的项必须解决，或在正文里明确降级为“待核”；`warn` 项逐条判断。同一处 `error` 的重写最多两轮，次数随任务记录，不要无限重写。普通措辞偏好只提示，不改核心判断。

## 七、非预测题的正例边界

- **机制题**（女性向游戏怎样吸引泛用户）：允许用“换装动作如何参与探索”“IP 联名怎样互相带受众”解释机制；有实际机制支撑的“续命”可以保留；不要求未来展望。
- **争议题**（游戏公司做 IP 是否不务正业）：两边最强论据都要有来源；可以给有条件判断；不把“不务正业”当禁词，也不靠反问句代替论证。
- **人工样本**是解释和争议分析，不能据此推断作者所有文章都要用预测结构；预测稿可以全篇零比喻。

## 八、交付

- 用 `writing_save_outline` 提交提纲并处理 issues；
- 用 `writing_save_work` 保存正文、brief、sources、outline；
- 保存后读取 `review` / warnings：`error` 修完再交付；仍有缺口的，在回复和 note 里写“草稿已保存，需核对”；
- 最终回复 5 行内：标题、稿件 id、字数、哪些是推算/待核、审校状态。
