# 语气档案：从语料到可用的写作先验

## 这一层解决什么

档案是一份写作提示，帮助模型参考作者常用的句长、段落节奏、用词和标点。它由用户的旧稿提炼成 Markdown，可在页面编辑。使用效果受语料质量、任务文体和模型影响，可用同题稿件对比判断。

## 语料怎么收

### 什么算语料

- 用户自己写的成段文字：文章、帖子、讲稿、长邮件、给自己的笔记、朋友圈长文。
- 对话里大段发出的内容，前提是用户自己写的（不是转贴、不是引用、不是 AI 代写）。

### 什么不算

- 用户转贴的别人的文章、合同、公告、说明书。
- 一两句话的指令（「帮我改一下」）——只看措辞偏好，不当文风样本。
- 翻译稿、明显的 AI 代写稿。宁可样本少，也不要混进不是他的句子。
- 已经署了别人名字的合写稿（除非用户说那部分是他写的）。

### 多少才够

样本少于 3 篇或正文不足约 1500 字时，只提炼最明显的几项。优先选同一场景下本人写的代表作，多篇复现的习惯更适合用于写作。这些数量是采样建议，不衡量模型生成的文章像不像作者。

同一场景的 10 篇不如跨场景的 5 篇。全是公众号推文时，写出来的东西会像推文；用户如果需要写别的文体，提醒他补样本。

### 三种来源

1. **上传文件**：`md / txt / docx / html / rtf`。PDF 先转格式（取文本会丢段落和标点）。旧版 `.doc` 先另存。
2. **直接粘贴**：`corpus add - --title "标题"`，从标准输入读。
3. **DSH 会话记录**：由插件收集（`$DSH_HOME/sessions` 在沙箱外，脚本读不到）。插件会把素材整理成 `corpus.md` 并给路径；读它，不要自己去翻会话目录。

### 命令

```bash
python scripts/writing.py corpus add 文章1.md 文章2.docx --origin article
python scripts/writing.py corpus add - --title "某篇旧稿"        # 粘贴
python scripts/writing.py corpus list
python scripts/writing.py voice stats
python scripts/writing.py voice stats --json
```

`--profile` 用于分开不同场景的档案（例如 `gongzhonghao`、`paper`），默认用 `~/.dsh-writing/voice/active` 指向的那个。`voice use <名字>` 切换。**一次只用一个档案写作**，不要把两份档案混着套。

### 隐私

- 语料、档案、草稿都只在本机；不要上传到外部服务，不要写进公开仓库。
- 引用原文当例句时，只摘写作上需要的部分；不要把语料里的个人信息、客户名、未公开数据带进新文章。
- 用户要求删除时，删 `<home>/voice/<名字>/` 整个目录，不要只删档案留语料。

## 先看统计，再读原文

`voice stats` 给的是**提示**，不是结论。它算的是：

| 指标 | 怎么用 | 不能怎么用 |
|---|---|---|
| 平均句长、长短句比例 | 判断节奏偏紧还是偏松；和原文对读 | 不能直接规定「每句不超过 N 字」 |
| 破折号、省略号、问号、感叹号 | 看标点习惯；档案里写「常用/几乎不用」 | 不能因为数量少就断定「不用」 |
| 第一/第二人称、大家 | 看怎么称呼读者、怎么表态 | 不能代替读原文判断语气 |
| 中英空格、英文词比例 | 看混排习惯 | 不能替用户统一术语 |
| 高频二字词 | 找候选口头禅，**必须回原文核对** | 二字切片会切出无意义的组合，不能直接当词表 |

统计之外，必须自己读 `corpus.md`。判断一条特征时，先问「这句话换个人写会不会也这样」；会，就不是特征。

## 提炼规范

### 一条特征的标准形状

```
- 可观察的行为（怎么写的）｜例：「原文摘句一」「原文摘句二」
```

- **至少一处逐字例句，重要特征尽量两处**。只有一处时，标「待验证」，不要写成定论。档案模板为了简洁只示范一处；`voice check` 只检查「有没有例句」，够不够要自己把关。
- 证据必须**逐字**摘，不跨段拼接，每句不超过 60 字。
- 一条只写一件事。不要把「句子短、爱用破折号、喜欢自嘲」塞进一条。
- 写「怎么用」，不是写评价。「句子偏短」是评价；「一段三到五句，长句后常跟一个短句收住」才是能指导写作的观察。

### 反面写法

| 不要写 | 为什么 | 改成 |
|---|---|---|
| 「文风简洁有力」 | 空泛，无法执行 | 「一段三到五句；常把长句拆成两个短句，后一句给判断」 |
| 「语言生动，富有感染力」 | 评价，不是特征 | 「会用具体场景开头，前两句不出现抽象名词」 |
| 「善用排比」 | 没有证据、没有用法 | 「排比只在段末出现，一次三项，用来收束」 |
| 「不用网络用语」 | 没核对过 | 「样本里没有出现『绝绝子』『yyds』这类词」 |

### 八类特征，各自问什么

1. **节奏与结构**
   - 句子偏长还是偏短？长短怎么交替？
   - 一段通常几句？有没有单句成段？
   - 段落之间靠什么推进：时间、因果、转折、举例？
2. **开头与结尾**
   - 第一段从场景、数据、问题还是判断开始？
   - 开头多快进入正题？有没有铺垫句？
   - 结尾是总结、动作、边界，还是抛问题？会不会拔高？
3. **人称与称呼**
   - 「我 / 我们 / 你 / 您 / 大家」各用在哪？
   - 怎么称呼读者？会不会替读者表态？
   - 谈自己的经验时用不用「你」？
4. **词汇**
   - 高频词、口头禅（写出现次数）。
   - 明显不用的词（例如从不写「赋能」「抓手」）。
   - 爱用哪类动词、哪类形容词？有没有生造词？
5. **判断与确定程度**
   - 直接下判断，还是先给条件？
   - 不确定时怎么说：「可能」「大概」「我猜」「还没验证」。
   - 会不会自嘲、反问、留一句「也可能是我错」。
6. **标点与混排**
   - 破折号、省略号、问号、感叹号、分号的使用。
   - 引号样式（`“”` 还是 `「」`），中英文之间加不加空格。
   - 数字写法：阿拉伯数字还是汉字；日期格式。
7. **幽默与情绪**
   - 有没有自嘲、冷幽默、口语插话？
   - 情绪强度：克制、直接、还是夸张？
   - 会不会用括号补充吐槽？
8. **结构偏好**
   - 爱不爱分点？分点用编号还是符号？
   - 小标题是陈述句、名词短语还是问句？
   - 有没有固定的收尾动作（回扣开头、给下一步）？

### 摘例句的规矩

- 逐字。错别字保留（那是语料的一部分），但不要为了「像」去模仿错别字。
- 不摘含隐私、客户名、未公开数据的句子；换一句同样能说明特征的。
- 每条例句不超过 60 字；需要上下文时，用「……」标省略，不改原句。

## 档案结构

```markdown
# 语气档案 · <名字>

更新：YYYY-MM-DD · 样本 N 篇（标题一、标题二…）· 置信度 较高/中等/较低

## 画像

一句话：这个人写东西时最像什么。不超过 50 字。

## 节奏与结构

- 观察｜例：「原文一」「原文二」

## 人称与称呼

- 观察｜例：「原文」

## 常用词与不用的词

- 常用：「词」（出现 N 次）｜例：「原文」
- 不用：「词」｜例：「样本里没有出现」

## 判断与语气

- 观察｜例：「原文」

## 标点与中英混排

- 观察｜例：「原文」

## 对话中学到的

- YYYY-MM-DD：用户原话「…」→ 以后怎么改

## 原文参照

> 最能代表语气的原文，不超过 150 字

> 再一段，不超过 150 字
```

`voice check` 会检查：一级标题、八个小节、每条特征是否带例句、原文参照是否至少两段、置信度和样本数/字数是否对得上。检查通过不等于写得好；它只挡结构缺失。

## 置信度与样本

- 样本数在档案头里写实际篇数，不写「若干」。
- 置信度按上表算，不凭感觉写「较高」。
- 新增语料后：重算统计、补新特征；**不要整份重写**，旧条目保留，矛盾的单独列出来问用户。
- 语料被删除时，依赖它的条目要一起删或标「证据已删」。

## 冲突与更新

### 新语料和旧条目矛盾

不要自己选一个。列给用户：

> 档案里写「几乎不用破折号」，但新加的三篇里有 11 处，多用在解释性插入。要以新样本为准，还是保留旧结论、把这批算作例外？

用户选完再改，改完跑 `voice check`。

### 对话里学到的

用户纠正措辞时：

1. 先照改当前这篇。
2. 用 `voice note` 记一条：`用户原话：「别用『值得注意的是』」→ 改法：直接说事，不加提示语`。
3. 同一条规律出现第二次，再把它挪进对应小节，写成带例句的特征。

只出现一次的偏好，留在「对话中学到的」，不要升级成全局规则；否则一次临时要求会污染整个档案。

### 用户说「不像我」

先让用户指出哪句不像，再对照档案:

- 档案里没有这条 → 补一条（要有证据）。
- 档案里有但没照做 → 是执行问题，改稿。
- 档案这条本身错了 → 改档案，并说明改了哪条。

## 用档案写作

- **频率匹配**：档案里说「偶尔用破折号」，就不要每段都放；说「一段三到五句」，就不要写成一句一段。样本里出现 3 次的习惯，不要在 800 字里用 10 次。
- **只借表达，不搬内容**：语料里的经历、数据、立场、人名，不能挪进新文章。语气是形式，不是素材。
- **档案优先于去 AI 味清单**：用户自己就爱用的「其实」「说白了」，即使清单上像口头禅，也保留。清单只处理那些让文字变空、变糊、变假的问题。
- **事实与文体优先于档案**：公文、技术说明要求准确克制，不能为了「像本人」把「应当」改成「我觉得」。
- **不确定时按档案，不按想象**。档案没写的，用中性中文；不要替用户发明新习惯。
- 引号、破折号、中英空格这类具体项，档案有明确写法就照档案；档案没写就按目标平台的习惯，全篇统一。

## 与插件的关系

- 在插件里添加旧稿时，样本和档案保存于 DSH 的本地数据目录。提炼时，插件把多篇样本的全文或节选交给 DSH 当前配置的模型；写作时，只附上选定的档案正文，旧稿本身不随写作任务提交。
- 后台提炼只用已随任务提交的样本，调用 `writing_voice save` 保存目标档案。后台文章按本次选定档案的提交版本写，明确选了「本次不用」就按文体写。请勿把样本或档案例句提交给搜索或其他服务。
- 不使用插件时，本参考文档里的 `voice stats`、`voice check` 等命令属于独立脚本，默认数据目录是 `~/.dsh-writing`。
- 会话记录收集（`collect`）只能由宿主做；脚本不读 `$DSH_HOME/sessions`。

## 检查清单

- [ ] 每条例句逐字，且能在语料里找到。
- [ ] 每条特征至少两处证据；单处证据标了「待验证」。
- [ ] 没有空泛评价（「简洁有力」「富有感染力」）。
- [ ] 置信度和样本数一致。
- [ ] 语料里的隐私、客户名、未公开数据没有进档案例句。
- [ ] 档案不超过 12000 字；超了先删复述语料的段落。
- [ ] 写完让用户过目，并说明「我按哪几条写」。
