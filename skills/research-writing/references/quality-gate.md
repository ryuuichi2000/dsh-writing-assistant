# 交付前的质量闸

这份清单不是词语黑名单。每一个命中都要回到上下文问：这句话是否空泛、重复、歧义、与文体不符？没有问题的地方不强行改。

## 优先级

冲突时按这个顺序：

1. **事实与确定程度**：不新增事实，不丢失否定、范围、条件、时间、归因；不把「可能」写成「确定」，不把「计划」写成「已经」。
2. **用户的当场指令与文体**：用户说「别动结构」就不重排；技术说明、公文要求正式克制，不强行口语化。
3. **语气档案**：用户自己的句长、用词、标点习惯。档案和下面的清单冲突时，档案优先。
4. **去 AI 味清单**：只处理确实让文字变空、变糊、变假的地方。
5. **默认中文**：没有档案、没有特殊要求时，按中性、清楚、自然的书面中文写。

原文没有细节时，改写可以保持概括；不能用编造的数字、引文、经历让句子「显得具体」。发现疑似事实错误，另行说明，不替用户猜一个答案。

## 事实与确定程度

逐类核对：

| 类型 | 要保留的 | 常见错误 |
|---|---|---|
| 数字 | 数值、单位、口径、时间 | 把「超过 3000」写成「3000」；换口径不说明 |
| 时间 | 发布/截止/生效时间，完成状态 | 「计划」写成「已经」；「近日」代替日期 |
| 归因 | 谁说的、什么场合、什么身份 | 把「专家认为」写成事实；把转述写成原话 |
| 否定与范围 | 「不」「仅」「除……外」「在……内」 | 改写时把否定丢掉；把局部写成全部 |
| 因果 | 相关 / 因果 / 可能 | 把相关写成导致；把推测写成结论 |
| 引文 | 逐字、说话人、出处 | 改写后仍加引号；翻译不标「译文」 |
| 预测 | 条件、概率、时间窗 | 把趋势写成必然；把判断写成数据 |

无署名归因（「有关部门」「业内人士」「研究表明」）没有具体来源时，要么补来源，要么降级成「现有公开信息没有说明」，不要留着一个空壳。

绝对判断（「必然」「彻底」「唯一」「所有」）要有范围限定或证据；没有就改弱。

## 十三类中文 AI 味

### 1. 机械对照句

- 信号：`不是……而是……`、`不仅……还……`、`不再只是……而是……`、`X 并不意味着 Y，而是 Z`。
- 保留：后半句纠正了真实误解，或两部分都提供独立信息。
- 改法：直接说事实；把对比改成转折、递进或重心移动。

### 2. 翻译腔连接词

- 信号：`对于……来说`、`基于此`、`围绕……展开`、`从某种意义上说`、`值得注意的是`、`与此同时`、`在这一背景下`、`使得……得以`、`就……而言`。
- 保留：确实表达同时发生、条件或范围，删掉会歧义。
- 改法：能删就删；能换短中文就换；能调句序就不加连接词。

### 3. 空泛大词

- 信号：`颠覆`、`革命`、`赋能`、`重塑`、`引领`、`开启新篇章`、`里程碑`、`深远影响`、`底层逻辑`、`组合拳`。
- 保留：有明确机制解释，或属于行业固定术语（如「闭环控制」）。
- 改法：落到具体动作、约束、成本、分工、结果。

### 4. 口号式收束

- 信号：`未来已来`、`这只是开始`、`新时代`、`真正的变革才刚刚开始`。
- 保留：几乎没有。引用别人的口号时保留归因。
- 改法：用一个具体判断收尾；回到已经发生到哪一步、还没发生什么。

### 5. 列表与排比成瘾 / 编号撑全文

- 信号：每段都是「粗体小标题 + 冒号 + 解释」；正文每节都用「第一、第二、第三」推进；能写成一段的拆成很多点。
- 保留：真正并列、需要逐项核对的内容；教学型步骤。
- 改法：并列项合并成自然叙述；编号改成时间、因果或场景推进；整篇编号压到一半以下。

### 6. 冒号、破折号、引号

- 信号：连续多句靠冒号展开；长破折号当万能连接；`“”` 和 `「」` 混用。
- 保留：冒号确实引出定义/列表；破折号承担插入或转折；档案里本人就爱用破折号。
- 改法：冒号改句号或拆句；破折号改逗号、句号；引号全篇统一（默认 `“”`，项目或档案要求 `「」` 就统一用）。

### 7. 营销稿与官样腔

- 信号：`持续深化`、`全面推进`、`积极探索`、`取得显著成效`、`高质量发展`、`打造闭环`、`注入新动能`。
- 保留：公文、正式材料里的固定表述（这类稿子按 `official-document-drafting` 的规则写，不套本清单）。
- 改法：有事实就把套话换成具体动作和指标；没有事实就删。

### 8. 判断强度失配

- 信号：过度谨慎——`在某种程度上可能会对……产生一定影响`；过度确定——`必然彻底改写整个行业`。
- 保留：证据强度确实只支持这个程度。
- 改法：证据有限就写清范围和条件；趋势明显就说「先影响谁、怎么影响」。

### 9. 开头、主体、结尾脱节

- 信号：第一段抛一个题，正文一直补背景，结尾没回到原题；中间有单看通顺、但与主线无关的段落；结尾突然拔高。
- 保留：真正需要环形结构时（首尾呼应且中间确实在推进）。
- 改法：先用一句话说清全文回答什么问题；逐段检查是否服务它；不能服务的删、并、挪；结尾回到前文已经展开的变量或判断。

### 10. 预告式收束

- 信号：`接下来要……`、`下一步是……`、`接下来的问题是……`、`下一篇会讲到……`。
- 保留：连载里确实需要指路，且只用一次。
- 改法：改成开放问题、冷结论、具体场景收束，或点出还没解决什么。

### 11. 抽象抬升

- 信号：`本质上`、`这件事`、`真正重要的是`、`归根结底`、`说到底`、`回到最初的那个问题`。
- 保留：确实需要总结全文的抽象层次，且后面有具体内容托住。
- 改法：`本质上` 改成机制句；`这件事` 改成具体所指；`真正重要的是` 改成事实后置，让重要性自己长出来。

### 12. 排版装饰

- 信号：标题前堆 emoji、箭头、分隔线；粗体当装饰；每段都有加粗重点。
- 保留：跳读确实需要的重点；流程箭头承载方向含义。
- 改法：删装饰，保留结构；重点靠位置和句子，不靠粗体。

### 13. 中文表达与混排

- 信号：层叠的「的」、`进行 + 动词`、被字句堆叠、四字排比、`随着……的发展` 开头、术语大小写不一、日期写法不一。
- 保留：正式文体需要被动句、四字格、名词化；固定术语和英文品牌名。
- 改法：长定语拆句；`进行测试` → `测试`；施事者明确时改主动；空泛排比换成具体动作；日期统一 `2026 年 2 月 26 日`；`token`、`API` 保持英文；品牌名用官方大小写。

## 文章级检查

改完逐段问：

- 开头提出的问题，结尾回应了吗？没有就改结尾，不要加一段拔高。
- 每一节是否只承担一个功能？两节功能相同就合并。
- 段落之间靠事情推进，还是靠「首先/其次/最后」硬粘？
- 多数小节是不是同一个形状（定义 → 三个分点 → 拔高）？至少换两节的走法。
- 有没有「资料卡」段落：单看通顺，但对主线没有作用？
- 结尾是否临时换题，或把局部判断拔高成时代命题？

## 语气档案的覆盖

- 档案里明确写「常用破折号」「爱用短句独立成段」时，本清单的对应条目让位。
- 档案只描述频率（「偶尔」），不要写成每段都用。
- 档案只借表达，不搬语料里的经历、数据、立场。
- 档案和文体冲突时（给政府部门的正式材料 vs 口语化档案），文体优先，并在交付时说明。

## `check` 的输出怎么读

```bash
python scripts/writing.py check <项目>
```

- **ERROR**：正文有引用但文末没有「参考资料 / 来源」小节。必须修，否则不能交付。
- **WARN**：占位符、无署名归因、绝对判断、重复句、引号混用、破折号偏密、篇幅过短。逐条判断：是问题就修，是误报就不管。
- **INFO**：空泛大词、冒号偏密、长句、来源未被正文用到。只作线索，不强制改。

`check` 只做机械检查，不判断事实真假，也不判断文章好不好。它过了，仍然要人工回查来源。

## 引用与归属

- **分析型 / 随笔**：正文不出现 `[1]`、`①②`、`（数据来源：…）`；出处写在句子里：根据《X》报道 / 据 X 统计 / X 数据显示 / 据 X 估算 / X 披露。
- **深度研究型**：行内归属，**或**文中编号 `[1]` + 文末「## 参考资料」一一对应；两种选一种，全篇统一，不许混用。
- 文末 `## 参考资料` 列全部来源（名称 + 日期 + 链接），条目和正文对得上。
- 一段里第二个来源写「另有……显示」，不要连着两句「根据」。
- 台账 `sources.md` 可以带序号；成稿里带不带编号按文体定。
- 孤编号（编号没有条目、条目没有编号）一律当 ERROR 处理。

## 交付清单

- [ ] 每个数字、日期、引文都能在 `sources.md` 找到；引文逐字，转述没加引号。
- [ ] 引用方式符合文体：分析型 / 随笔没有编号；深度研究型用编号时与「## 参考资料」一一对应。
- [ ] 没有无署名归因撑着关键判断。
- [ ] 判断强度和证据匹配；「可能」「计划」没有被写成「确定」「已经」。
- [ ] 开头与结尾在回答同一个问题；每节服务主线。
- [ ] 没有为了工整硬凑三段式、编号列表、排比或口号收尾。
- [ ] 没有 `style-analysis.md` 第五、六节列的 AI 味症状（句子层 + 结构层）。
- [ ] 比喻只在真正解释机制时使用；没有就不写，不设“全篇 2—3 处”的配额（深度研究型一处也不要）。
  （分析型的任务拆解、预测/机制/争议分流、提纲与证据口径见 `analysis-playbook.md`）
- [ ] 深度研究型另查三项：没有推论、没有未来展望、没有行动建议；结论分「已确认 / 单一来源 / 无法确认」。
- [ ] 语气像用户本人；档案里的习惯按频率使用，没有堆砌。
- [ ] `check` 没有 ERROR；WARN 逐条判断过。
- [ ] 占位符要么替换，要么在交付说明里列出。
- [ ] `preview.html` 能打开，选中正文能出按钮。
- [ ] 交付说明写了：语气档案、假设、待核点、来源数量。
