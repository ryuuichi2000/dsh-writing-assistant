# 深度研究型文章：规范

面向大众的深度研究文章：只做研究与分析，写给普通读者看。

范围不限于政策：政策、法规、司法解释、行业事件、公司或产品、技术、争议话题都行，看用户给的题目。

从 [研究与写作方法](deep-research-methods.md) 选择题目需要的研究角度，按证据缺口检索，梳理关键变化和同期比较。篇幅、读者、语气档案、引用方式和检索许可按插件本次任务单执行。方法文件负责研究步骤，本文件规定文体与交付。

## 一、相对分析型的增量约束（硬要求）

| 维度 | 分析型 | 深度研究型（本文件） |
|---|---|---|
| 比喻 | 按 `analysis-playbook.md`，不设数量配额 | **一处也不要有**。不用「像 / 如同 / 无异于 / 好比 / 等于」把事实换成意象，也不要用比喻解释概念。材料自己带比喻时，用引号引原话并注明出处 |
| 句式 | 短句、判断句、允许一句成段 | 同样要短，但**不许用修辞性反问、不许用「不是 A，是 B」的对偶**撑节奏 |
| 引用 | 行内归属，不出现编号 | 行内归属，**或**文中序号 `[1]` + 文末「## 参考资料」一一对应；二选一，不许混用 |
| 推论 | 可以给判断（基于证据） | **不给推论**：只写材料支持的结论；「所以」「意味着」后面必须是材料直接支撑的句子 |
| 展望 | 可以写趋势判断（带依据） | **不写未来**：不预测、不展望、不写「下一步将」「未来会」「值得期待」 |
| 建议 | 可有可无 | **不写行动建议**：本文只做研究与分析；材料本身提出建议时，转述并注明是谁提的 |
| 语气 | 可以带态度、可以有作者在场 | 严谨、克制；作者不出场（不写「我认为」「在我看来」，判断用「材料显示」「据此可以确认」） |
| 排版 | 常规 | 精确：标题层级只用 `##` / `###`，编号连续，表格列对齐、数据完整，日期统一 `YYYY 年 M 月 D 日`，数字与单位之间空格统一，不靠加粗堆重点 |
| 篇幅 | 按本次任务单 | 按本次任务单 |

## 二、信源规范（硬规则）

### 2.1 优先级（能用高的就不要用低的）

| 优先级 | 信源 | 例子 |
|---|---|---|
| 一手 | 政府 / 部委 / 法院官网、公报、政策原文与正式解读；公司公告、年报、招股书、监管披露；统计数据、年鉴、专利、裁判文书；发布会 / 演讲记录、一手访谈 | gov.cn、cac.gov.cn、nppa.gov.cn、court.gov.cn、交易所披露、国家统计局 |
| 权威二手 | 行业协会官网、权威机构报告、主流党媒与专业媒体 | 游戏工委、伽马数据、新华社、人民日报、省级党媒 |
| 行业媒体（仅前两类都找不到时） | 可靠行业媒体 | 游戏日报、游戏葡萄；必须注明转载来源 |
| 禁用 | 来源不明的自媒体、营销号、未标注出处的转载、AI 生成的「资料站」 | — |

### 2.2 操作规则

1. 关键事实至少 **2 个独立来源**交叉验证，其中至少 1 个一手；两家转载同一通稿不算独立。
2. 法规 / 文件类：**必须引到原文条款**，条款编号不能错，不能拿二手报道当原文。
3. 每条引用优先找**官方 URL**；不用聚合站、门户转载（toutiao、163、sina、qq 等）当来源。
4. 找不到一手来源时，明确写「未找到官方来源，以下基于 XX 报道」，并标实际发布机构。
5. 日期：区分事件日期、数据所属期间、原文发布日期、更新日期与报道日期。沿时间线使用历史材料时标明它适用的时期，对现状判断另核截至研究日的资料。
6. 非政策题材的一手来源：公司数据以经审计的年报/招股书为界，产品数据以官方公告或应用商店榜单为界，
   玩家/用户数据以平台公开数据为界；访谈写清是谁、什么时候、什么场合。
7. 查不到就写 `〔待核：…〕` 或直接写「公开信息未能确认」，不用确定语气。

## 三、结构

### 3.1 三块

1. **`# 标题` + 一段摘要**。摘要只做两件事：①核心内容 3—5 条（简洁列，不展开）；②下文从哪几个方面展开（一句）。
   摘要里不罗列数据、不下判断、不写"本文将带你……"。开头不加作者、日期、版本号、目录、分隔线。
2. **主体**。按主题选结构（3.3），章节自己命名。
3. **结论**。只写材料支持的结论；分三档写清：哪些已确认、哪些只有单一来源、哪些公开信息无法确认。
   **不推测、不展望、不提建议。**

> 署名放文末（「文/署名」），下面接 `## 参考资料`（或 `## 来源`）。

### 3.2 深度要求

- 篇幅以任务单为准：按正文汉字计（标点、链接和文末参考资料不计），成稿落在任务的 ±10% 以内；超出先删，不要以「可读性」为由放宽。每个核心结论至少一条直接证据。
- 允许有「没有答案的部分」：写明为什么查不到、缺哪类材料。
- 不做没有材料支撑的趋势判断；不写「行业普遍认为」，除非指明是谁、在哪说的。
- 图表只在确实帮助理解时用；用了就校验（表格列对齐、数据完整、编号连续）。

### 3.3 五种参考骨架（选最接近的，**不要照搬**）

| 骨架 | 适用 |
|---|---|
| A 条文 / 文件型 | 新规出台、法规修订：核心条款 → 适用范围 → 争议点 → 结论 |
| B 事件型 | 行业事件、发布会、战略动作：事实链 → 各方说法 → 关键分歧 → 结论 |
| C 案例 / 裁判型 | 判例、处罚、典型案例：案情 → 依据 → 裁判规则 → 结论 |
| D 对比型 | 新旧版本、同类政策、同类产品：维度对齐 → 差异 → 差异的原因 → 结论 |
| E 问题拆解型 | 一个待回答的问题：拆成 3—5 个子问题 → 逐个给证据 → 合起来回答 |

**灵活组合四条**：选最接近的当骨架；可跨骨架组合；章节按内容自己命名（不照抄「一、二、三、四」）；
没价值的删、缺的维度加。

## 四、引用写法

二选一，全篇统一：

**方式一（行内归属，默认）**

> 据《2025 中国数字娱乐产业 IP 发展报告》，数字娱乐产业 IP 衍生品市场规模达 753 亿元。
> 另据宝可梦公司官网公布的数据，截至 2026 年 3 月，系列软件全球累计出货超 5.15 亿份。

**方式二（文中序号 + 文末对应）**

> 数字娱乐产业 IP 衍生品市场规模达 753 亿元[1]。截至 2026 年 3 月，宝可梦系列软件全球累计出货超 5.15 亿份[2]。
>
> ## 参考资料
>
> 1. 《2025 中国数字娱乐产业 IP 发展报告》，2026 年 9 月，https://…
> 2. 宝可梦公司官网「公司数据」页，2026 年 3 月，https://…

规则：

- 编号从 `[1]` 连续编，**每个编号必须在参考资料里有对应条目**；没有条目的编号是错误。
- 参考资料条目要有：名称、发布者（能确定时）、日期、链接（有就给）。
- 一段里出现第二个来源，用「另据……」「此外」引出，不要连着两句都「根据」。
- 二手转述写「据 X 转述」，不冒充一手。
- 法条原文用 `>` 引用块，引完整句子并标条款号；一份文件最多直接引两处，每处不超过 40 字。

## 五、两件必须做的校验

### 5.1 四维自查（写完先做）

- **信源**：每条关键事实能不能追到可靠来源？条款原文和编号准不准？案例是官方还是企业自述？
- **逻辑**：结论是不是材料直接支持的？有没有「证据只到 A、结论写到 B」？
- **一致性**：前后有没有矛盾？数字、日期、条款号是否一致？
- **边界**：有没有偷偷写推论、预测、展望、建议？有就删。

### 5.2 对抗式审查（换成审稿人视角，真的找问题）

1. **结论对抗**：最重的三条结论，逐条问「材料够不够？有没有反例？换个人会不会得出别的结论？」
2. **事实对抗**：原文引用准不准？编号对不对？来源是官方还是转述？前后数字矛盾吗？
3. **材料充分性对抗**：有没有哪一节其实是靠常识补的？有没有「看起来有依据、其实只有一条二手」的段落？

发现问题就改：补前提、降确定程度、或删掉那句。

### 5.3 去 AI 味

按 `quality-gate.md` 过一遍（**但比喻一律为零**）。`style-analysis.md` 是分析型的作者样本观察，不是本文件的必读项。
保留：条款引用块、表格清单、准确的编号、克制的分析语气。

## 六、交付前自检

- [ ] 开头是 `# 标题` + 一段摘要，没有作者 / 日期 / 目录 / 分隔线。
- [ ] 关键事实 ≥2 个独立来源，其中 ≥1 个一手；法规类引到原文条款。
- [ ] 引用方式全篇统一；若用编号，每个编号在参考资料里都有条目，且条目有名称和日期。
- [ ] 没有门户转载当官方 URL；没有把二手当原文。
- [ ] 日期核过：事件、统计和发布各自的时间准确，旧资料与现状有明确区分。
- [ ] 结论分三档（确认 / 单一来源 / 无法确认），没有推论、没有预测、没有建议。
- [ ] **全文没有一处比喻**；没有修辞性反问，没有「不是 A，是 B」对偶。
- [ ] 排版精确：标题层级只用 `##`/`###`，编号连续，表格列对齐，日期格式统一。
- [ ] 做过对抗式审查（至少把最重的三条结论反问过一遍）。
- [ ] 去过 AI 味：没有公式化连接词、空泛大词、口号收尾。

## 七、与分析型的区别（一眼看得出来的三处）

1. **开头**：分析型是场景 / 硬数据 / 设问起手；深度研究型是 `# 标题` + 摘要。
2. **比喻**：分析型按 playbook，不设数量配额；深度研究型一处也没有。
3. **结尾**：分析型重新定性、可以带一句态度；深度研究型只写材料支持的结论，不推测、不展望。

信源标准与校验动作来自用户提供的研究规范（一手优先、交叉验证、原文条款、对抗式审查）；
范围、结构、语言和引用按「面向大众的写作」重写，和 `style-analysis.md`、`quality-gate.md` 配套使用。
